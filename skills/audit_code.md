# Skill: Audit Code

## Objective
QA Engineer（@qa）として、`src/` 内のコードを監査し、依存関係の欠落、構文エラー、未処理エラー、セキュリティ脆弱性、ロジックバグ、および**リファクタリングによる既存機能のデグレード（先祖返り・破損）**を検出・修正する。

## Rules of Engagement
- **対象ディレクトリ**: `src/`
- **基準ドキュメント**: `docs/spec.md`
- **デグレード防止**: リファクタリング時は、既存の要件や機能が壊れていないか、インターフェースの整合性が保たれているかを最重要視する。
- **直接コミット**: 修正が必要な箇所は直接 `src/` 配下のファイルを上書き・修正する。
- **CLI連携**:
  - プロジェクト横断のセキュリティチェック、型整合性の検査、リファクタリング前後の差分レビューには **Claude Code CLI** を活用する。
  - 生出力は破棄せず Run ディレクトリへ保存する: `claude -p --output-format text --max-budget-usd 1.00 "<code-or-diff>" | tee docs/runs/$RUN_ID/raw/<NN>-claude-qa-<topic>.md`

## Instructions
1. 仕様書（`docs/spec.md`）と `src/` 内の実装・差分を比較検証する。
2. 構文エラー、インポート漏れ、型定義の不整合、セキュリティホール、デグレードの有無を検出する。
3. 問題箇所を修正し、修正済みのクリーンなコードを `src/` に反映する。

## 作業記録（必須）
- `track_progress.md` に従い、監査完了直後に `docs/runs/$RUN_ID/journal.md` へ `@qa` エントリを追記する。
- **検出した問題は必ず全件記録する**。`Findings / Issues` には以下の表を用いる:

  | 検出項目 | 深刻度 (High/Med/Low) | 対応 (修正済み/未対応) | 備考 |
  |:---|:---|:---|:---|

- 修正しなかった項目は「未対応」として理由付きで残す（黙って落とさない）。この表がそのまま `report_run.md` の QA セクションになる。
- 修正後にコミットする: `git add -A && git commit -m "fix(qa): <修正概要> (<RUN_ID>)"`
